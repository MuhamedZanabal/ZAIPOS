# CSV import and spreadsheet export boundaries

The shared importer parses complete CSV records, including quoted CRLF/LF fields and escaped quotes. It preserves field contents; domain-specific import code remains responsible for normalizing names or validating exact fils. Empty physical lines are ignored. Headers must be unique after trimming, nonempty and no more than 256 columns. Every data row must have exactly the header width. Unterminated quotes, stray quotes, trailing text after a closing quote, NUL/control data and invalid Unicode fail before any domain mutation begins. Imports are bounded to 10 MiB of JavaScript characters, 10,000 data rows and 65,536 characters per field. Prototype-shaped headers are ordinary own keys in null-prototype records.

Exports quote both headers and values and double embedded quotes. Formula-shaped text, including whitespace-prefixed and full-width operators, receives a leading apostrophe. Numeric strings such as 1.251 remain textually exact. Nonfinite numbers, nested objects, unknown additional columns and unsupported control characters are rejected. Blob download URLs are released after dispatch. Import transaction atomicity and backend monetary validation remain enforced by the existing domain RPCs.

The apostrophe is an intentional spreadsheet safety prefix, not part of the original business field. It is not silently removed by the importer: doing so would reactivate untrusted formulas. Therefore spreadsheet CSV is not a lossless interchange format for formula-shaped values. A future exact export channel must use a typed format or explicit schema/version, not remove this protection. Full export pagination and authoritative-fils selection remain separate unresolved production tasks.

No CSV escape is universally safe across every spreadsheet and repeated editing/save/reopen cycle. Treat exported untrusted fields as text when importing into a spreadsheet; do not enable formula execution or external content. This repository verifies emitted bytes and parser behavior, not every spreadsheet application's execution behavior. See [OWASP CSV Injection](https://community.owasp.org/attacks/CSV_Injection) for the interoperability limitation.

Verification: src/lib/csv.test.ts covers multiline/quoted fields, malformed records, duplicate headers, prototype keys, formula-shaped headers/values, alternate operators, exact three-decimal strings, Unicode and input bounds. Nine assertions reproduced the old boundary failures before the implementation changed.

Inventory import additionally requires a nonblank SKU and explicit nonnegative count (up to three decimals) for every row. Blank is never interpreted as zero. Duplicate or unresolved SKUs, counts beyond NUMERIC(12,3), and an exported center name that differs from the selected destination reject the whole request before the atomic reconciliation RPC. UI tests reproduce and prevent both the blank-to-zero and silently-skipped-unknown-SKU defects. This does not turn the current per-SKU lookup into a measured bulk import benchmark or certify ambiguous-response retry UX; those remain follow-up audit work.
